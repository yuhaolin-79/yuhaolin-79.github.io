2. interface、abstract class、class 分别负责什么？

这三个概念很容易混在一起，但它们的职责其实不一样。

4. abstract class：抽象类负责复用公共代码

抽象类介于接口和具体类之间。

比如 AbstractList 是一个抽象类，它帮助很多列表类提前写好了一部分通用逻辑。

但是它本身还不是完整的类，所以不能直接创建对象：

抽象类的意义在于：

多个子类有共同逻辑时，可以把公共代码放到抽象类中，避免重复实现。

比如 ArrayList 和 LinkedList 都属于 List 家族，它们有一些共同的行为，就可以通过抽象类复用。

5. class：具体类才是真正可以 new 的对象

真正可以创建对象的是具体类，比如：

ArrayList 和 LinkedList 都是完整的类，所以可以实例化。

它们都实现了 List 接口，但底层实现方式不同。

ArrayList 底层更接近数组结构，适合随机访问。
LinkedList 底层更接近链表结构，适合频繁插入删除。

所以接口规定“你要能做什么”，具体类决定“你到底怎么做”。

13. 最后总结

关于 Java 中的接口、抽象类和继承关系，可以用几句话总结：

interface 主要规定能力，告诉类应该能做什么。

abstract class 主要复用公共逻辑，帮助子类减少重复代码。

class 是真正可以创建对象的具体实现。

List list = new ArrayList(); 表示用接口类型引用具体对象，这是面向接口编程。

向上转型后，对象本身不变，但变量类型会限制你能调用哪些方法。

接口的 default 方法是接口提供的默认实现，主要用于扩展接口功能，同时兼容旧代码。

所以：

可以理解为：

右边决定真正创建的对象，左边决定我们用什么角度去看待这个对象。

这也是 Java 面向对象编程中非常重要的一种思想。
